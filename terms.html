3. Usage limits

The gadgets read your Jira data through Atlassian's Jira API and run on Atlassian's Forge platform. Atlassian sets limits on both, and those limits can change what a gadget shows.

  • Hourly allowance. Jira limits how many calls an app can make each hour, for the app as a whole and in some cases for each site. The app-wide allowance is shared by every customer of the app, so it can run out while your own use is normal. When it runs out, the gadget says so and can show data again when the next hour starts (UTC).
  • Time limit. Forge stops a function that runs too long. A gadget has about 18 seconds to read Jira. If Jira answers slowly, the gadget shows what it has read and says that the result covers only part of the data. If the time runs out before a later step, the gadget shows an error that asks you to narrow the filter or the period.
  • Issue caps. Each gadget reads at most the number of issues listed on its documentation page and says when it stopped.
  • Changes by Atlassian. The provider cannot raise these limits for one customer. If Atlassian changes them, the provider will update the documentation when it learns of the change. A reduction in what a gadget can show that comes from a change in Atlassian's limits is not a decrease in the functionality by the provider.
