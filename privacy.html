Privacy and data

Summary

The gadgets run on Atlassian's Forge platform with no remote components, which is the design the Runs on Atlassian program requires (Forge's own check, forge eligibility, says each version is eligible). They have no servers of ours, no database, no remote calls and no external network access. Jira data is read when someone opens a dashboard, turned into numbers in memory, shown on the screen, and discarded.

Who is responsible

The vendor, Eitan Plaks, is responsible for how these apps process your Jira data. Atlassian is not.

Roles under data protection law

When someone opens a gadget, the app reads Jira data on behalf of the customer. For that data the customer is the controller and the vendor is a processor. The vendor's code runs on Atlassian's Forge platform, so Atlassian acts as a sub-processor under Atlassian's Forge data processing addendum. The vendor does not receive, store or read this data, and the apps are built so that it does not appear in the logs the vendor can see.

The vendor is a controller only for the messages people send to support (see Support correspondence below).

A data processing addendum is part of the terms.

What is stored

  • By us: nothing from Jira. The apps use no storage and no database.
  • By Jira: each gadget's settings (board, JQL filters, number of months or days) are kept by Jira as part of the dashboard. The settings form hands them to Jira when you save, and Jira stores them with the dashboard; the apps keep no copy.
  • Logs: when an unexpected error happens, the app writes the error name and status to the Forge log. For a programming error in our own code it also writes the error message; it never writes a JQL filter, an issue key or any issue content. Each dashboard view also writes one line with a count of Jira API points used (a number, no content). The vendor can see Forge logs for the app.
  • Retention: there is no Jira data to keep, so there is no retention period.

Personal data in Jira

The gadgets show names that Jira returns, such as the assignee of an issue or the person who added an issue to a sprint. They do not copy, keep or send those names anywhere.

Support correspondence

This is the only personal data the vendor holds, and the vendor is its controller.

  • What: the e-mail address and name of the person who writes to support, the message, and anything attached to it.
  • Why: to answer the request and to keep a record of the answer. The legal basis is the vendor's legitimate interest in answering and recording requests. It is not used for marketing and is not sold.
  • Where: support is by e-mail only. Mail to the support address is forwarded by Cloudflare (Email Routing) to the vendor's mailbox at Google (Gmail). Both providers may process it in several countries, including the United States. There is no public issue tracker.
  • Who gets it: Cloudflare, which forwards the mail, and Google, which hosts the mailbox. The vendor passes details to Atlassian only when a request concerns a security incident or Atlassian itself escalates it, and then only what that case needs.
  • Transfers: for transfers to the United States the vendor relies on the safeguards those two providers publish, such as standard contractual clauses or Data Privacy Framework certification.
  • How long: the vendor deletes support messages once 12 months have passed since the last message in the thread, at a yearly clean-up each December, so no later than 24 months after it. A record kept because the law or Atlassian requires it is the exception.

Where Jira data is processed and stored

The vendor stores no Jira data in any country. The processing happens on Atlassian's Forge infrastructure. Atlassian's Forge documentation says an app invocation may sometimes run in a different location from the one that hosts your Jira site; Atlassian's data processing addendum covers that case. The Forge log holds no Jira data.

Who gets the data

Nobody outside Atlassian, which hosts the apps and provides the Jira API. The vendor shares no Jira data with any other person or company, and the apps declare no external hosts. Support messages are covered in the section above.

Your rights

Because the vendor holds no Jira data, a request to see, correct or erase that data goes to your Jira administrator, who controls it. For anything the vendor holds, such as a support message, write to the address below. You can also complain to Israel's Privacy Protection Authority or, if you are in the EU, to your national data protection authority.
